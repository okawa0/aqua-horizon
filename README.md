## **実装時に意識したポイント**

- JavaScriptをdefer属性で読み込み、DOMの構築を優先
- ナビゲーションメニューとヒーロー画像の位置が逆のデザインを、wrapperで囲みflex-directionをcolumn-reverseに指定して対応
- 画像をWebPに変換しパフォーマンス配慮
- ヘッダーとフッターに同じハンバーガーメニューを配置するデザインを、ボタンのaria-controls属性で打ち分けを実現
- ハンバーガーボタンにaria-expandedを付与しアクセシビリティ対応

- keyframeを用いた無限ループを使用
- 全ての`<img>`にwidth / height属性を指定し、レイアウトシフト（CLS）を抑制
- ファーストビューのヒーロー画像にfetchpriority="high"を付与し、LCPの改善を図った

### ヒーロー画像の出し分けに`<picture>`を採用した理由

基本要件のvisible-pc / visible-sp（`display: none`による表示切り替え）は、**非表示側の画像もブラウザがダウンロードしてしまう**という問題があります。

ヒーローはPC用3枚（計約950KB）／SP用3枚を出し分ける箇所のため、この方式ではスマートフォンでの初回表示時に、表示されないPC用画像まで読み込むことになります。

そのため、ヒーローのみ`<picture>` + `media`属性によるレスポンシブイメージで実装し、**ビューポートに応じて必要な画像だけを取得する**構成としました。あわせてスライダーのマークアップがPC/SPで重複していたものを1つに統合しています。

※ ヘッダーの電話番号・住所など、画像以外の要素の出し分けは要件どおりvisible-pc / visible-spを使用しています。

### ナビゲーションのコンテンツ切り替えにARIAタブを使わなかった理由

7項目（トップ / 店舗 / コース一覧 / スタッフ / お客様の声 / Q&A / お問合せ）は、本来ページ単位のグローバルナビです。

`role="tablist"`のARIAタブパターンで実装すると、①URLが変わらず直リンク・共有ができない ②ブラウザバックが効かない ③JavaScriptが動かない環境で何も表示されない、という問題が起きます。

そのため**リンク + URLハッシュ**で実装し、現在地は`aria-current="page"`で示しました。また`hidden`属性はHTMLに直接書かずJavaScript側で付与しているため、**JavaScriptが動かない場合は全セクションが表示され、ページ内アンカーとして機能します**。

詳細は [docs/tab-navigation-design.md](docs/tab-navigation-design.md) に記載しています。

### Q&Aアコーディオンをネイティブ機能で実装

`<details name="faq">`の排他開閉（同じname属性のうち1つだけ開く）を利用し、**JavaScriptなし**で実装しました。

開閉アニメーションは`@supports selector(::details-content)`で囲んでいるため、非対応ブラウザでは即時開閉にフォールバックします。

### お問合せフォームのバリデーション

`novalidate`でブラウザ標準のバリデーションを止め、エラー文言・表示位置・フォーカス制御を自前で実装しています。

- `aria-invalid` / `aria-describedby`でエラー文と入力欄を関連付け
- 送信時、最初のエラー項目へフォーカスを移動
- エラーは色だけでなくアイコンとテキストでも表示（色覚多様性への配慮）
- 入力欄の`font-size`は16px以上（iOSでの意図しない拡大を防止）
- 一度エラーになった項目のみ入力中に再検証（入力途中でエラーを出さない）

※ バックエンドがないため、送信は完了メッセージを表示するモックです。画面上にもその旨を明記しています。
